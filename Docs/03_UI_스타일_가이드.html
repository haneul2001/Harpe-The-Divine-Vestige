사신 컨셉의 어두운 화면에 얹히는 UI. 회색과 진한 보라만 쓰고, 채도는 체력에만 남긴다.

2026-09-03 확정 · 이후 만드는 모든 UI는 이 문서를 따른다

01

방향

게임 화면이 이미 어둡고 보랏빛이다. 여기에 채도 높은 UI를 얹으면 UI만 화면에서 떠오른다. 그래서 UI는 배경보다 한 단계 더 가라앉히고, 시선을 끌어야 하는 정보 — 남은 체력 — 에만 붉은 기운을 남긴다.

원본 UI 팩은 금색이다. 그대로 쓰면 컨셉과 정면으로 충돌하므로 밝기만 남기고 다시 칠해서 쓴다.

05

규칙

채도 높은 색 금지

특히 노랑·주황·형광. 잔상이 노란색이던 때가 있었는데, 맞을 때마다 번쩍여서 "UI가 쨍하다"는 인상의 가장 큰 원인이었다.

체력의 붉은 기는 남긴다

완전히 회색·보라로 통일하면 막대가 "체력"으로 안 읽힌다. 채도를 낮추되 색상은 유지한다.

곱하기 틴트로 색조를 바꾸려 하지 말 것

곱하기는 채널 순서를 보존해서 금색은 갈색이 될 뿐이다. 반드시 픽셀을 램프로 다시 칠한다.

픽셀아트는 정수 배율로만

1.7배 같은 배율은 픽셀을 뭉갠다. 9-slice를 쓸 땐 pixelsPerUnitMultiplier = 1/배율로 맞춘다.

글자에는 검은 외곽선

막대 색 위에 얹히므로 그림자 하나로는 밝은 구간에서 뭉개진다.

원본 팩을 직접 수정하지 말 것

리컬러본을 Haneul_Branch/Art/UI에 따로 만든다. 팩을 업데이트해도 작업이 날아가지 않는다.

06

새 UI 그림을 넣을 때

  1. 출처를 정한다

    일반 UI는 2D Pixel Quest Vol.3, 상점은 Honeti PixelArtGUI. 섞지 않는다.

  2. 램프로 리컬러한 사본을 만든다

    밝기(0.30R + 0.59G + 0.11B)를 구해 5단계 램프에 매핑하고 알파는 그대로 둔다. 원본의 슬라이스와 9-slice 테두리 정보를 사본에 그대로 복사한다.

  3. 늘어날 부분의 테두리를 잰다

    눈대중 금지. 픽셀을 읽어 프레임의 안쪽 홈 위치를 확인하고 9-slice 테두리를 잡는다. 잘못 잡으면 채움이 테두리를 덮는다.

  4. PixelBar로 조립한다

    막대류는 Code/UI/PixelBar.cs가 프레임·채움·잔상·칸나눔·숫자를 다 만들어 준다. 치수 상수도 거기 모여 있다.

확인은 사람이 한다. 색과 치수는 계산으로 맞출 수 있지만 "쨍한지"는 띄워 봐야 안다. 새 UI를 넣으면 반드시 실제 게임 화면에서 한 번 보고 판단할 것.
